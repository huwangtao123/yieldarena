# Yield Arena

**Park Capital. Fuel Agents.**

Yield Arena is a Tempo-native arena where `fxSAVE` principal stays parked, daily yield becomes continuous play budget, and AI agents spend that budget across competitions.

> **Research / Experimental**
> This project is an MVP. It is designed to prove one loop clearly: park principal, mint yield, fund an agent, enter a live competition, and keep playing while budget remains.

## Why This Exists

Some agent games are genuinely fun, but they are still hard to discover, hard to keep funded, and hard to turn into a persistent optimization loop.

That creates three problems:

- good agent competitions stay fragmented across separate sites and APIs
- agents do not have a continuous budget to keep entering matches
- strategy iteration is weak because there is no shared arena layer for identity, funding, and live competition flow

Yield Arena is the layer above that.

It does not start by inventing a new game.
It starts by making good agent competitions discoverable and continuously playable.

## Thesis

`fxSAVE` is the parked capital layer.

Yield Arena uses the yield from that parked principal as the only spendable budget.

Agents do not consume principal.
They consume the budget generated by yield.

That is the core product idea:

- principal stays parked and withdrawable
- yield becomes play budget
- agent accounts receive small competition-ready float
- the arena keeps entering matches while budget remains

## MVP Scope

Today, the MVP proves one live competition end to end:

- `MPP Checkers` is the current live competition
- `Private Challenges` is visible in the product, but still pending

The MVP is intentionally narrow:

- one arena
- one live competition
- one funding loop
- one auto-run path

This keeps the story sharp:

`fxSAVE principal -> yield -> play budget -> live competition`

## How It Works

```text
User principal (fxSAVE)
        |
        v
  Daily yield accrues
        |
        v
  Play budget becomes available
        |
        v
  Yield Arena funds an agent account
        |
        v
  Agent enters a live competition
        |
        v
  Arena keeps playing while budget remains
```

## Current Competition Loop

The current live loop looks like this:

1. Select an agent in Yield Arena
2. Select the live competition
3. Start the run
4. Arena prepares the agent profile if needed
5. Arena routes protocol budget or wallet budget
6. Arena enters the live competition
7. Arena auto-plays turns when it is the agent's move
8. Arena keeps the run open while budget remains

## Quick Start

### 1. Install dependencies

```bash
npm install
```

### 2. Make sure Tempo is set up

This project assumes you already have a working Tempo wallet:

```bash
tempo wallet -t whoami
```

### 3. Run the app

```bash
npm run dev -- --host 127.0.0.1 --port 4173
```

Open:

`http://127.0.0.1:4173/`

### 4. Run the autonomous agent script

```bash
npm run agent:run -- --reset --agent-id yield-arena-bot --nickname YATest --strategy "Play aggressively when captures open up."
```

## Funding Model

The MVP currently models two funding sources:

### Protocol Budget

Starter budget that helps new agents get into the arena.

### Wallet Budget

Budget derived from the user's yield side.

### Play Budget

The combined spendable budget shown in the UI.

The product rule is:

**principal is not spent**

Only the yield-derived budget is consumed by the arena loop.

## Protocol-Realistic Model

The long-term model is:

- owner capital stays parked in `fxSAVE`
- yield becomes allowance
- the arena tops up an agent account with small float
- the agent account spends into competitions
- leftover balance can be swept back

## Important Current Limitation

There is one important honesty line in the current MVP:

The arena now auto-plays live checkers turns, but the external competition still sees the **main Tempo wallet signer** as the actual player identity.

In practice, that means:

- the arena keeps a separate registered competition profile
- the arena also keeps an agent account model
- but live `MPP Checkers` requests still execute through the main Tempo wallet today

So the product loop is real, but the full `per-agent real signer` model is not finished yet.
